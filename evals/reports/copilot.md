## How to read it

- **The judge is another model** (`openai/gpt-5.6-luna`) than the copilot's (`openai/gpt-6-luna`), to reduce self-grading bias. It is still a model of the same family and may share its blind spots, so the literature scores are indicative; the human spot-check below is the check on the judge.
- Execution accuracy: the expected value (from the generator's ground truth) appears in the answer; for a count of 1-10, the answer must say it is hidden. Numbers are matched with a stated tolerance for averages, medians, p-values and survival percentages.
- A question is scored only if a reference query on the database agrees with the ground truth; otherwise it is listed as a pipeline gap (the copilot cannot be right about data the pipeline got wrong).
- Tool choice: the tool a good plan uses ran successfully. Structured tools (cohort count, survival) are preferred over SQL where they fit.
- The differencing guard's memory is cleared before each data and literature question, so each answer is scored on its own; the red team tests the guard.
- Literature answers are quote-grounded: each claim carries verbatim quotes from the abstracts it cites, checked by string matching in code; claims whose quote is not found (or that add numbers their quotes lack) are dropped and counted. The judge then rates whether the cited abstract supports the claim.
- Some literature questions can also be read as data questions ("how does dd-cfDNA change after transplant?"); when the copilot answered from the center's data instead, the answer has no citations and no RAGAS score, and the row shows '-'.
- Answer relevancy uses strictness 1 (one generated question per answer): the judge is cached, so more would repeat the same question.
- Intervals cover sampling noise over these questions only. All data is synthetic.
